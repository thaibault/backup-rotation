backup-rotation

This script allows you to create a local or remote backup rotation for your files.

Project Status

Use case

Daily, weekly and monthly backups of any folders with a single Bash script and a systemd timer. Each run copies the sources via rsync, packs them as compressed archive, optionally encrypts them and removes backups older than their retention time. Recipients get an e-mail on failures (and optionally on success), a monitoring service can be informed as well.

Installation

Copy the script and the systemd units into place and enable the timer, which runs the backup every night at 01:00 (Europe/Berlin):

install -D --mode 755 backup-rotation.sh /usr/bin/backup-rotation
install -D --mode 644 backup-rotation.service backup-rotation.timer \
    --target-directory /etc/systemd/system
systemctl enable --now backup-rotation.timer

On Arch Linux the included "PKGBUILD" builds a package via "makepkg --install". The script needs "bash", "rsync", "tar" and "find" and downloads its library bashlink if it is not installed. It is also available via "npm install backup-rotation".

Configuration

"/etc/backupRotation" is a Bash file which overrides the defaults. At least the sources have to be mapped to their target folders, optionally followed by e-mail addresses to notify:

BR_SOURCE_TARGET_MAPPINGS=(
    ['/home']='/mnt/backup/home admin@example.com'
    ['server:/srv/data']='/mnt/backup/data'
)
BR_NAME=workstation

Sources can be anything rsync accepts, also remote locations like "server:/srv/data". Targets have to be local folders, e.g. a mounted disk or network share. "BR_NAME" names this machine in reports. Run "backup-rotation" once by hand to check the configuration.

Rotation

Each target gets the folders "daily", "weekly" and "monthly". On the first day of the month the backup goes to "monthly", on Saturdays to "weekly", otherwise to "daily". Daily (and weekly) backups of these days are links to it. Backups are kept for 14, 56 and 365 days:

BR_MONTH_DAY_NUMBER=1
BR_WEEK_DAY_NUMBER=6
BR_NUMBER_OF_DAILY_RETENTION_DAYS=14
BR_NUMBER_OF_WEEKLY_RETENTION_DAYS=56
BR_NUMBER_OF_MONTHLY_RETENTION_DAYS=365

Outdated backups are only removed after a successful run, so a failing source never loses its last backups.

Encryption

If the password file "/etc/backupRotationPassword" is not empty, archives are encrypted with "gpg" and get the extension ".tar.gz.gpg". Decrypt one with:

gpg --decrypt --output backup.tar.gz 13-11-2026.tar.gz.gpg

Notifications

E-mails are sent via "msmtp", so it needs a working "/etc/msmtprc". Without "BR_SENDER_E_MAIL_ADDRESS" no e-mails are sent. "BR_MONITORING_URL" receives a JSON document with "source", "target" and "error" via "PUT" after each backup:

BR_SENDER_E_MAIL_ADDRESS=backup@example.com
BR_SEND_SUCCESS_E_MAILS=false
BR_MONITORING_URL=https://monitoring.example.com/backups

Own commands

"BR_COMMAND" replaces the rsync and tar step, "BR_ENCRYPT_COMMAND" the encryption and "BR_CLEANUP_COMMAND" the removal of outdated backups. "BR_POST_RUN_COMMAND" runs after each successful backup and its result is reported. Commands can use "$source_path", "$target_path" and "$target_file_basepath" (the backup file path without extension). "BR_VERBOSE=true" prints what happens.

BR_POST_RUN_COMMAND='rclone copy "$target_path" remote:backups'
